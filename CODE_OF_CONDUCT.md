# Code Of Conduct

This policy covers project issues, pull requests, reviews and other project
spaces. Everyone may participate regardless of background or experience.

## Expected Behavior

- Discuss the technical problem with respect and provide actionable feedback.
- Critique ideas and code, not a person's identity or worth.
- Accept corrections, respect boundaries and keep discussions relevant.
- Protect other people's private data and give appropriate attribution.

Harassment, discrimination, threats, sexualized remarks, doxxing, impersonation,
spam and repeated personal attacks are not acceptable.

## Reporting And Moderation

Use GitHub's **Report content** control on the affected issue, pull request or
comment. Choose **Report to repository admins** when that option is enabled.
For platform abuse, use **Report abuse to GitHub Support** or GitHub's
[abuse-reporting process](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam).
Reports to GitHub Support are handled by GitHub, not the project maintainers.

No separate private moderation address is currently designated. Do not open a
public issue containing sensitive personal information. Repository owners should
enable reporting to repository admins before opening the project to public
participation, as described in
[REPOSITORY_SETUP.md](.github/REPOSITORY_SETUP.md).

Maintainers may clarify expectations, ask participants to stop, hide or remove
content, lock conversations, or restrict participation according to severity and
repetition. Moderation should be proportionate and consistent. Reports should
be shared only with people needed to address them; absolute confidentiality
cannot be guaranteed.

Security vulnerabilities follow [SECURITY.md](SECURITY.md), not the public
moderation or support issue forms.
